# 策略

策略决定 avdkit 是否可以代表调用方产生某类副作用。它与能力不同：策略表达“调用方是否允许”，能力表达“当前主机能否完成”。允许一项策略不会让缺失的工具或尚未实现的操作变为可用。

策略通过 `KitConfig.policy` 注入。默认组合避免隐式下载和许可接受，同时保留调用方明确请求的 SDK 包管理和 AVD 文件操作。

## 隐式安装

`implicit_install` 控制其他操作能否顺带下载依赖，默认值为 `false`。

例如，Android CLI 在空 SDK 中创建设备时可能自动安装 emulator、platform-tools 或系统镜像。默认策略不允许把这种行为交给底层工具：这类操作的契约是先报告缺少的依赖，由调用方决定是否另行执行安装。当前会触发隐式安装的执行入口尚不可用。

它不影响调用方明确发起的安装操作；显式安装由另一项策略控制。

## 显式包管理

`explicit_install` 控制是否允许安装、更新或删除 SDK 包，默认值为 `true`。

这个设置只授予执行权限。对应工具、平台和具体操作仍须在能力矩阵中可用。

## 许可接受

`license_acceptance` 控制是否允许 avdkit 代表调用方接受 Android SDK 许可：

- `never`：不代为接受，默认值。
- `allow`：允许需要安装依赖的操作代为接受。

当前只支持默认的 `never`。配置为 `allow` 时，创建 `Kit` 会返回 `capability_unavailable`，原因是 `not_implemented`，而不是在执行安装时临时询问或自动接受。

许可是否已经接受，通过 `<sdk>/licenses/<license-id>` 中是否存在预期哈希判断。文件缺失、不可读、格式无效或哈希不匹配都视为未接受。判断过程不解析工具的交互提示，因为提示文本会随工具版本变化。

## 文件操作

`file_operations` 控制是否允许直接移动 AVD、改写配置或执行其他文件级操作，默认值为 `true`。

现有 INI 读写原语会保留未知配置和原有顺序；原子替换、备份以及通过公共门面移动或改写 AVD 尚不可用。因此，这项策略目前只接受默认值，不会单独使文件修改能力变为可用。

## Android CLI 指标

`android_cli_metrics` 控制是否覆盖 Android CLI 自身的指标设置：

- `inherit`：不传指标参数，沿用用户已有设置；这是默认值。
- `no_metrics`：传入 `--no-metrics`。

当前只支持 `inherit`。公开模型保留 `no_metrics`，但传入该值会像其他非默认策略一样在创建 `Kit` 时被拒绝。

## 工具偏好

`KitConfig.tool_preference` 保留操作到具体工具的路由覆盖。它与副作用策略分开存储，但采用相同的配置验证方式。当前只接受空的覆盖表，不应用调用方自定义偏好。

## 当前配置边界

当前版本只接受整套默认策略。任一非默认策略都会使 `Kit::new` 返回：

- 错误码 `capability_unavailable`；
- 原因码 `not_implemented`；
- 指向具体配置项的消息，例如 `policy.license_acceptance`。

验证在环境探测和任何副作用之前完成，因此配置不会被部分应用。工具偏好、超时和备份目录的非默认值也遵循这一规则。

## 不受策略影响的规则

以下规则不能通过配置关闭：

- Android CLI 调用始终显式传入 `--sdk=<path>`，避免 `~/.androidrc` 改变目标 SDK。
- 许可状态只根据 SDK 中的哈希文件判断，不依赖提示文本。
- 不通过删除或改写用户全局文件来绕过认证。例如，不清空 `~/.emulator_console_auth_token`。
